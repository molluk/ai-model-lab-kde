# AI Model Lab KDE v3.2 — несколько GPU и независимых моделей

Самостоятельная GUI-лаборатория для CachyOS/KDE Plasma на PySide6 (Qt6).
**Всё приложение, профили, встроенные бенчмарки, журналы и отчёты находятся в одной папке:**
`~/AI/AI-Model-Lab`. GGUF физически остаются в своих каталогах `/home/USER/AI/models`.

## Обновление с v3.1

1. Останови только само окно старой версии AI Model Lab (действующие серверы можно оставить).
2. Распакуй ZIP, открой терминал в папке `AI-Model-Lab-KDE-v3.2`.
3. Выполни `bash ./install.sh` — sudo не нужен. Установщик **не перезаписывает** твои существующие `models.json`, `settings.json` и `data/`.
4. Запусти `~/.local/bin/ai-model-lab` или одноимённый ярлык KDE.
5. Если нет PySide6: `sudo pacman -S pyside6`.
6. Проверка Python: `cd ~/AI/AI-Model-Lab && python3 -m unittest discover -s tests -v`.

Запускавшиеся **ранее через v3.1** серверы на 8080 распознаются по старому `data/llama.json` и доступны для контролируемой остановки. Новый запуск не убивает их автоматически.

## Одновременная работа двух и более моделей / GPU

Каждый профиль имеет **свой API-порт** и собственную настройку `GPU` (индекс CUDA/NVIDIA или UUID). Процесс запускается отдельно; нет глобального `pkill`, автоматической замены уже работающей модели или общей очереди на одном порту.

Пример настройки в редакторе:

| Профиль | Порт | GPU | Контекст |
|---|---:|---:|---:|
| `blend-q4` | 8080 | `0` | 131072 |
| `coder-30b` | 8081 | `1` | 131072 |
| `qwen38-27b` | 8082 | `0` | 131072 |

*Указанные порты и GPU — пример, а не автоматическое изменение твоих старых профилей.* По умолчанию у импортированных профилей v3.1 порт 8080, GPU не зафиксирована. Чтобы два профиля могли работать вместе, сначала назначь **разные порты** и при необходимости **разные GPU**.

Установка GPU использует `CUDA_VISIBLE_DEVICES` только для процесса конкретной модели. Пустое поле GPU означает автоматический выбор llama.cpp; он может задействовать несколько карт в зависимости от запуска и сборки. Введённый индекс должен соответствовать установленной видеокарте. GPU-карты видны в `nvidia-smi -L`, а также в редакторе профиля.

**Объём VRAM, питание и RAM не суммируются автоматически**: каждая модель должна физически умещаться в выбранное устройство с учётом настроек `-ngl`, MoE-offload и KV. На текущей конфигурации с единственной RTX 2080 Ti выбор GPU `1` не заработает, пока в системе нет второй поддерживаемой карты.

**WebUI** по-прежнему использует существующие настройки внешних OpenAI-совместимых API. Для подключения второго сервера его адрес нужно отдельно зарегистрировать в Open WebUI (например `http://127.0.0.1:8081/v1`). Приложение не переписывает настройки WebUI автоматически.

## Интерфейс v3.2

### Вкладка «Модели»

- Цветные статусы рядом с названием: **серый** (не запущена/остановлена), **жёлтый** (загрузка/занят порт), **зелёный** (готова), **красный** (сбой).
- **Одна кнопка** у выбранной модели: запуск, остановка, загрузка, предупреждение о занятом порте. Другие модели не останавливаются.
- Колонки «Модель», «Статус», «Контекст», «Назначение»: ширина регулируется мышью; размеры сохраняются в `settings.json`. Есть горизонтальная прокрутка.
- Описание выбранной модели прокручивается.
- Внизу слева — живые логи выбранной модели из её собственного журнала; кнопка открывает отдельное окно полного/последних 2 МБ лога, а внешний редактор может открыть весь файл без ограничений.
- Двойной щелчок по модели → вкладка «Настройки», выбор нужного профиля.

### Вкладка «Настройки»

Редактор разбит на четыре вкладки:

1. **Основные**: ID, название, назначение, путь/шаблон GGUF, контекст, порт, GPU, дополнительные аргументы.
2. **Sampling**: temperature, top_p, top_k, min_p, repeat_penalty.
3. **Память / KV**: GPU layers, n_cpu_moe, parallel slots, batch, microbatch, flash attention, KV offload, формат K/V.
4. **Мультимодальность**: mmproj, image_min_tokens, thinking_off, Jinja, reasoning off.

Здесь же **Добавить**, **Клонировать** (с отдельным свободным портом), **Удалить**. Удаление работающего профиля требует подтверждения и предварительной остановки *только* этого экземпляра; GGUF не удаляется.

Предыдущие версии `models.json` автоматически архивируются в `data/backups/` (до 20 последних копий) при изменении профилей.

По умолчанию действует **сохранение по кнопке**. При включении опции «Автосохранение профиля» изменения записываются автоматически после короткой паузы. При переключении с несохранённого профиля предлагается сохранить, не сохранять или отменить переход. Действующий процесс не меняет параметры на лету — новые параметры применяются после перезапуска данного экземпляра.

### Трей KDE

Нажатие на «X» открывает выбор: **«Свернуть в трей»**, **«Закрыть приложение (серверы оставить)»**, **«Отмена»**. Если система не предоставляет системный трей, первый вариант недоступен. В трее есть пункты «Открыть», «Тесты», «Управление», «Закрыть приложение». Закрытие GUI не убивает ни llama.cpp, ни другие AI-сервисы. Если в программе идёт тест или операция запуска/остановки, закрытие GUI блокируется до безопасного завершения; спрятать в трей можно.

### «Управление»

Таблица экземпляров llama.cpp показывает модель/GPU/порт/статус/PID. Можно остановить один выбранный экземпляр, все управляемые llama.cpp или отдельно управлять Open WebUI, Agent Office, ComfyUI. Остановка «всех AI-сервисов» требует подтверждения.

### «Тесты»

Выбирается **конкретный работающий экземпляр** и его порт. Скорость, арифметика и длинный контекст работают на любом локальном API-порту; телеметрия NVIDIA берётся с указанного GPU профиля (если он задан). Агентные Android P1/P2 через Pi пока разрешены **только на :8080**, поскольку существующий провайдер `local-lab` на нём настроен: для других портов нужен отдельный Pi provider. Это намеренное ограничение против невалидных сравнений.

Бенчмарки и отчёты лежат в `benchmarks/`, `data/reports/`, `data/logs/`. Дополнительные внешние архивы не нужны. Исходники Android не редактируются, но Pi `read,grep,find,ls` **не является ОС-песочницей**.

## Что проверено, а что нет

- Python syntax compile core/multi/bench/gui, shell syntax и встроенные тесты.
- Реально подняты **два локальных мок-сервера на отдельных портах** и проверена независимая остановка и проверка PID; при этом **LLM и CUDA не загружались**.
- Установка через bash проверяется в изолированном HOME, без изменения настоящего домашнего каталога пользователя.
- Qt GUI на реальном KDE/Wayland/X11 **не удалось запустить в тестовом контейнере** (PySide6 там отсутствует). Поэтому поведение трея и GUI на CachyOS нужно проверить после установки.
- Перед серьёзным тестом сверяй контекст Pi `~/.pi/agent/models.json` и фактический контекст llama.cpp.
