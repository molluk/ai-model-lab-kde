# AI Lab — ярлыки для CachyOS (Fish / KDE / XDG)

## Установка

1. Распаковать ZIP, открыть Fish в каталоге `AI-Lab-Shortcuts-v1`.
2. Выполнить:

```fish
bash ./install.sh
```

Установщик добавит 9 ярлыков в меню приложений и на рабочий стол, а сам лаунчер скопирует в `~/ai-model-lab/shortcuts/ai-lab.sh`. **Не трогает** существующий `~/ai-model-lab/ai-model-lab.sh`, проект example-android-project, Pi `models.json`, систему пакетов и рабочие архивы бенчмарков. Запуск моделей происходит только после нажатия ярлыка.

## Ярлыки

- Blend Q4 — 128K, GGUF Q4_K_M, thinking off;
- Blend Q5 — **32K, экспериментально**, GGUF Q5_K_M;
- Qwen3.8-27B — 128K, GGUF Q4_K_M, thinking off;
- Qwen3-Coder-30B — 128K, GGUF Q4_K_M, reasoning off;
- Devstral Small 2 24B — **32K, экспериментально**, GGUF Q4_K_M;
- Стоп llama.cpp — только собственный, запущенный данным комплектом процесс;
- Статус — проверка моделей, путей, Pi и портов;
- Запуск Open WebUI — локальный `127.0.0.1:3000`;
- Открыть Open WebUI — в браузере.

Все GGUF-серверы слушают **127.0.0.1:8080**, а Open WebUI — **127.0.0.1:3000**. По умолчанию сервер запускается в терминале **на переднем плане**: окно оставлять открытым; для остановки нажать `Ctrl+C` или использовать ярлык «Стоп llama.cpp» (только когда процесс запущен этим комплектом).

Сервер не переключает модель автоматически, если порт 8080 уже занят: сначала закончите бенчмарк и остановите предыдущий сервер. Это защищает от случайного прерывания текущего запуска.

## Общие параметры llama.cpp

Проверенные для Blend Q4, а также ранее использованные для Qwen3.8 и Coder параметры:

```
-ngl 99 -np 1 -b 1024 -ub 256 -fa on
--no-kv-offload --cache-type-k q8_0 --cache-type-v q8_0
--jinja --reasoning off --temp 0.7 --top-p 0.8
--top-k 20 --min-p 0 --repeat-penalty 1
--metrics --host 127.0.0.1 --port 8080
```

Для Blend и Qwen3.8 дополнительно: `--chat-template-kwargs '{"enable_thinking":false}'`. Для Qwen3-Coder / Devstral эта настройка не применяется.

Контекст `-c 131072` у Blend Q4, Qwen3.8 и Coder; для Blend Q5 и Devstral консервативно задан `-c 32768`, т.к. 128K для них не подтверждён этим проектом. Изменить можно в `~/ai-model-lab/shortcuts/ai-lab.sh` внутри функции `select_model`, но тогда фиксируйте новые параметры в истории испытаний.

## Исправление пути к модели

Пути для Blend Q4, Qwen3.8 и Coder заданы по вашему описанию; при несовпадении ищется **один однозначный GGUF** по точной квантизации внутри `/home/USER/AI/models`. Для Blend Q5 и Devstral доступен такой же поиск. При нескольких совпадениях запуск отклоняется, чтобы не выбрать случайную модель.

Посмотреть реальные пути без запуска:

```fish
bash ~/ai-model-lab/shortcuts/ai-lab.sh doctor
```

Если файла нет, можно задать путь через переменную, например в Fish:

```fish
set -lx AI_LAB_CODER_30B_GGUF '/home/USER/AI/models/.../actual-coder.gguf'
bash ~/ai-model-lab/shortcuts/ai-lab.sh model coder-30b --dry-run
```

Переменные из одной интерактивной сессии Fish **не наследуются ярлыками рабочего стола**, поэтому для постоянного исправления лучше скорректировать путь внутри установленного `ai-lab.sh` либо привести файлы к ожидаемой структуре.

## Проверки и диагностика

```fish
# Показать полную команду запуска модели, ничего не выполняя
bash ~/ai-model-lab/shortcuts/ai-lab.sh model blend-q4 --dry-run

# Состояние локальных сервисов
bash ~/ai-model-lab/shortcuts/ai-lab.sh status

# Ручной запуск через Fish (тот же, что у ярлыка)
bash ~/ai-model-lab/shortcuts/ai-lab.sh model qwen38-27b
```

Логи находятся в `~/.local/state/ai-lab-shortcuts/logs/`. Путь лога печатается перед стартом, его можно передать `ai-benchmark.py --server-log` для точных серверных таймингов.

**Важно:** `models.json` в Pi не изменяется. Для тестов необходимо заранее проверить `contextWindow` и `maxTokens` Pi. При лимите 16K в Pi даже сервер с 128K не обеспечит корректный агентный прогон.

Если KDE показывает вопрос «Доверять и запустить» для ярлыка с рабочего стола, разрешите запуск после проверки его содержимого. Никаких сетевых запросов в Интернет, Git-команд или изменений Android-проекта эти ярлыки не выполняют. Open WebUI может выполнять собственные функции соединений, если ранее был так настроен, — этот установщик настройки не меняет.
