# AI Model Lab KDE v3.7 — запуск моделей в OpenCode и Pi

Самостоятельное графическое приложение для **CachyOS / KDE Plasma**, написанное на Python + Qt6 (PySide6).

Все файлы приложения, скрипты тестов, профили, отчёты и логи находятся в **одном каталоге** `~/AI/AI-Model-Lab/`. Большие GGUF-файлы **не копируются**, а используются на прежних путях `/home/USER/AI/models/`.

## Установка обновления поверх v3.4

1. Полностью **закрой старое окно** AI Model Lab (при выборе «Закрыть приложение» серверы llama.cpp продолжат работу). Не запускай два экземпляра GUI одновременно.
2. Распакуй `AI-Model-Lab-KDE-v3.6-CachyOS.zip` в произвольную папку.
3. Открой Fish в распакованном каталоге `AI-Model-Lab-KDE-v3.6`, выполни:

   ```fish
   bash ./install.sh
   ```

4. Запусти `~/.local/bin/ai-model-lab` либо ярлык **AI Model Lab — KDE**.
5. Если Python не видит PySide6, установи через `sudo pacman -Syu pyside6`.
6. Проверь тесты:

   ```fish
   cd ~/AI/AI-Model-Lab
   python3 -m unittest discover -s tests -v
   ```

Установщик сохраняет существующие `models.json`, `settings.json`, `data/reports`, `data/logs`, `data/instances` и настройки Pi. Перед обновлением копирует прежние программные файлы в `data/backups/release-<дата>/`. Новые тесты и исходники программы устанавливаются в тот же каталог. Старые отчёты не удаляются.

## Изменения v3.4

### «Модели» — теперь основная рабочая вкладка

Таблица содержит **7 столбцов**: «Модель», «Статус», «Контекст», «GPU», «Порт», «PID», «Назначение». Между заголовками есть вертикальные разделители. Ширину каждого столбца меняй перетаскиванием границы мышью; приложение запоминает значения в `settings.json`. Для старого четырёхколоночного списка v3.2 размеры автоматически заменяются на безопасные значения для новых 7 колонок. При узком окне появляется горизонтальная прокрутка таблицы.

Под списком кнопки **Добавить**, **Клонировать**, **Удалить**, **Изменить**. Двойной щелчок по строке открывает редактор именно этой модели. Удаление профиля не удаляет GGUF. Работающий экземпляр нельзя удалить без подтверждения и предварительной остановки.

GPU и порт остановленной модели показывают **назначение в профиле**, а PID показывается как `—`. У работающей модели GPU, порт и PID берутся из метаданных настоящего процесса; для длинного UUID наведением на ячейку можно увидеть полное значение. Если профиль изменён в процессе работы, новые параметры вступят в силу после его перезапуска.

Цвета статуса: **серый** — не запущена/остановлена, **жёлтый** — загружается или порт занят, **зелёный** — работает, **красный** — ошибка. Справа — прокручиваемое описание и одна кнопка запуска/остановки выбранного экземпляра. Слева внизу — живой лог и окно полного журнала.

### «Управление» — только реальные запущенные процессы

Теперь список моделей **не дублируется**. Отображаются только управляемые работающие `llama.cpp`: имя, GPU, порт, PID, состояние и время работы. Если никого нет — сообщение «Нет активных экземпляров llama.cpp».

Можно открыть лог выбранного экземпляра, остановить **только его**, остановить все управляемые llama.cpp. Отдельно остались сервисы **Open WebUI**, **Agent Office**, **ComfyUI** и общий останов. Сторонние процессы по имени не убиваются (никакого общего `pkill`).

### Адаптивная компоновка

- Метрики GPU / VRAM / RAM / скорости не сплющиваются: в узком окне прокручиваются горизонтально.
- Таблица моделей прокручивается горизонтально; правая и левая панели имеют разумные минимальные размеры.
- На вкладках «Модели», «Управление», «Тесты», «Отчёты» и «Настройки» добавлена вертикальная прокрутка всего содержимого при маленькой высоте окна.
- Строки и кнопки сервисов больше не схлопываются до полосок при минимальном размере.
- Поле «Найденные GPU» — отдельное многострочное окно с вертикальной прокруткой и возможностью скопировать UUID.
- Из верхней шапки удалены дублирующие кнопки «Тесты» и «Управление»: осталась только **«Обновить»**. Основная навигация — вкладками.

## Как выбрать одну из двух одинаковых RTX 2080 Ti 22 ГБ

**Рекомендуется выбор по UUID**, поскольку индексы `0` и `1` могут измениться при перестановке GPU или изменении системной конфигурации.

Проверь реальные UUID через терминал:

```fish
nvidia-smi --query-gpu=index,name,uuid,memory.total --format=csv
```

В новой версии редактора «Настройки» → «Основные» есть выпадающее поле **GPU (UUID или индекс)**. Оно перечисляет реально обнаруженные NVIDIA GPU с именами и UUID. Выбери строку нужной карты: программа сохранит именно полный UUID. Допускается ручной ввод индекса `0` или `1`; пустой выбор «Авто» означает автоматический выбор устройств llama.cpp и **не гарантирует**, что процесс использует лишь одну физическую GPU.

Пример для двух независимых серверов (UUID в таблице — условные, не копируй их как настоящие):

| Профиль | Выбранная карта | API-порт | GGUF |
|---|---|---:|---|
| `blend-q4` | UUID **первой** RTX 2080 Ti | `8080` | Blend Q4 |
| `blend-q4-copy` | UUID **второй** RTX 2080 Ti | `8081` | Тот же Blend Q4 |
| или `coder-30b` | UUID **второй** RTX 2080 Ti | `8081` | Qwen3-Coder |

Для двух Blend нажми **«Клонировать»** на вкладке «Модели». Приложение создаст новый alias и подберёт свободный порт. Перейди в редактор копии, выбери UUID второй видеокарты и сохрани. Для каждой модели в итоге будут свои сервер, PID, порт и VRAM.

При запуске выбранного профиля применяется `CUDA_VISIBLE_DEVICES=<UUID>` и `CUDA_DEVICE_ORDER=PCI_BUS_ID` **только к его дочернему процессу**. Перед стартом проверяется, что запрошенный индекс/UUID присутствует в выводе `nvidia-smi`. Если карты нет, запуск отменяется вместо молчаливого переключения на другую. Порт занят — запуск также отменяется; никакой работающий сервер не останавливается автоматически.

**GPU, RAM и питание:** выбранная видеокарта не делит свои 22 ГБ VRAM с соседней. Каждой модели нужно достаточно памяти под веса и KV-кэш. Две RTX 2080 Ti могут существенно увеличить нагрузку на блок питания; перед установкой второй карты оцени БП и охлаждение. Не предполагай, что текущий 700-ваттный БП гарантированно подходит для двух карт при полной загрузке.

**WebUI:** серверы работают на `http://127.0.0.1:8080/v1` и `http://127.0.0.1:8081/v1`. Подключения к обоим адресам нужно настроить отдельно в Open WebUI; приложение не изменяет его конфиг без разрешения.

**Android Pi P1/P2:** пока поддерживается только сервер на `8080`, поскольку конфигурация `local-lab` в `~/.pi/agent/models.json` указывает этот адрес. API-бенчмарки скорости/логики/контекста можно запускать на любом выбранном экземпляре. Нельзя сравнивать P1/P2 на разных портах без корректного перенастроенного провайдера и одинаковых условий.

## Что остаётся из v3.2

- Четыре вкладки редактора модели: **Основные**, **Sampling**, **Память / KV**, **Мультимодальность**.
- Сохранение по кнопке или опциональное автосохранение, резервные копии профилей.
- Независимый запуск нескольких серверов, подтверждение остановки, отдельные логи.
- Системный трей KDE: при нажатии X можно свернуть GUI в трей, закрыть только GUI (оставив серверы) или отменить.
- Встроенные офлайн-скрипты тестов и хранение отчётов внутри одного каталога.
- Все операции над Android-проектом в испытаниях только средствами Pi `read,grep,find,ls`; **это не полноценная ОС-песочница**. Для секретных проектов требуется отдельная изоляция.

## Проверки и ограничения

- Проверены компиляция Python-модулей и Bash-синтаксис, модульные тесты на выбор GPU/UUID, два независимых мок-сервера, защиты PID, изменение порта профиля и установка в тестовом HOME с сохранением пользовательских файлов.
- **Настоящая загрузка GGUF на двух RTX 2080 Ti и поведение Qt-окон на CachyOS здесь не проверялись**: окружение разработчика не имеет этих GPU и PySide6. Точный графический результат необходимо проверить на твоём рабочем столе.
- `CUDA_VISIBLE_DEVICES` работает для CUDA-сборок llama.cpp. Выбор GPU по UUID не переключает автоматически провайдер Pi, не объединяет память и не синхронизирует несколько независимых серверов.

## v3.6 — запуск выбранной модели в OpenCode / Pi

На вкладке **Модели** появилась кнопка **«Открыть выбранную модель в… ▾»**:

- **OpenCode** — откроет новое окно Konsole, подключив OpenCode к **выбранному запущенному экземпляру llama.cpp**. Передаётся фактический порт, а не фиксированный 8080. Поддерживаются форматы конфигурации OpenCode 1.x и 2.x; версия определяется через `opencode --version`. В OpenCode 2 используется `--standalone`, чтобы не подключиться к ранее запущенному общему сервису с другой моделью.
- **Pi** — использует существующий провайдер `local-lab` в `~/.pi/agent/models.json`, если адрес и контекст действительно совпадают с текущим сервером. В противном случае создаёт **отдельный** `models.json` в `data/clients/pi/<alias>/<port>/`. Глобальный файл Pi не переписывается. Такая отдельная среда Pi **не наследует автоматически** все глобальные расширения и настройки `~/.pi/agent/`.
- **Скопировать локальный API /v1** — полезно для других совместимых клиентов.

Перед открытием клиент проверяет, что модель запущена, отвечает на `/health`, а `/props` возвращает правильный alias. Если модель не запущена или порт занят посторонним сервером, открытие блокируется. GUI не запускает и не останавливает серверы автоматически по нажатию этой кнопки.

В **Настройки → Общие** есть поле **«Рабочая папка OpenCode / Pi»** и кнопка «Обзор». По умолчанию используется домашний каталог пользователя; чтобы работать с Android-проектом, выбери его каталог осознанно и нажми **«Сохранить настройки программы»**. Pi и OpenCode могут иметь полномочия на изменение файлов; запуск клиента не создаёт ОС-песочницу. Параметры модельных серверов и конфигурации агентных клиентов — разные вещи.

**Важно:** пользовательские `~/.config/opencode/opencode.json`, `~/.opencode/opencode.json` и `~/.pi/agent/models.json` ни установщик, ни новый лаунчер не изменяют. OpenCode получает временную конфигурацию через переменную окружения, Pi — через проверенный существующий профиль либо отдельный каталог конфигурации внутри AI Model Lab. Проверять реальное подключение необходимо на целевой CachyOS: установленная версия клиента и локальный API могут требовать индивидуальной совместимости.

### Что сохраняется после перезапуска

| Состояние | Где хранится | Когда сохраняется |
|---|---|---|
| Название, alias, назначение, путь GGUF, порт, GPU, контекст, sampling, KV | `models.json` | По кнопке «Сохранить профиль» или при включённом автосохранении |
| Пути, параметры хранения логов, автосохранение, ширины колонок, рабочая папка клиентов | `settings.json` | По кнопке «Сохранить настройки программы»; часть параметров (например, ширина колонок) — автоматически |
| Журналы и отчёты | `data/logs/`, `data/reports/` | По мере работы; старые данные могут удаляться по настроенному сроку хранения |
| PID/порт/GPU/статус управляемых экземпляров | `data/instances/` | При запуске и остановке сервера; статусы сверяются с реальными PID после старта GUI |
| Изолированная модель для Pi при несовпадающем порте | `data/clients/pi/` | При открытии клиента |
| Графики GPU/RAM текущей сессии, активная вкладка, геометрия окна | Оперативная память | Пока не сохраняются как история рабочего стола |

При выходе **только из GUI** управляемые `llama-server` продолжают работать. После перезагрузки компьютера запуск серверов автоматически не настроен: профили останутся, но модели нужно загрузить снова. Клиентские сессии сохраняются по правилам самих OpenCode и Pi, а не как часть истории GUI.


## v3.6 — исправление запуска и клиент по умолчанию

- Исправлены CSS фигурные скобки в `gui.py` внутри `STYLE = f'''...'''`, приводившие к `NameError: name 'background' is not defined`.
- Для каждого профиля в «Настройки → Основные» добавлено поле «Клиент по умолчанию»: Pi / OpenCode.
- В карточке модели основная часть кнопки «Открыть в Pi/OpenCode» запускает выбранный клиент. Стрелка справа открывает меню альтернатив и копирование адреса API.
- Выбор хранится в `models.json` в поле `preferred_client`. Уже существующие профили не переписываются установщиком; для них действует безопасное значение по умолчанию: Coder/Devstral → OpenCode, остальные → Pi. Когда пользователь сохранит профиль, значение запишется в файл.
- Конфигурации установленного OpenCode и Pi по-прежнему не перезаписываются. У каждого сервера свой адрес и порт.

### Публикация на GitHub

Исходники можно выложить публично, но **не публикуй локальные `data/`, `models.json`, `settings.json`, журналы, отчёты и репозитории Android**. Для открытой публикации используются `models.example.json` и `settings.example.json`. Перед созданием публичного репозитория отдельно проверить и обобщить два Android STB бенчмарка из `benchmarks/prompts/`: их примеры ориентированы на существующий частный Android-проект.

## v3.7 — отдельный выбор клиента, подсветка строки и установка зависимостей

- В главном списке выделенная модель имеет контрастный фон даже после потери фокуса таблицей.
- Вместо слитной кнопки-меню теперь две самостоятельные части: кнопка **«Открыть в»** и выпадающий список **Pi / OpenCode**. Рядом доступна кнопка `?` с инструкцией по установке клиента.
- Выбор Pi или OpenCode **не запускает модель**. Смена сохраняется в `models.json` сразу, с резервной копией прежнего конфигурационного файла. Это работает и с остановленной моделью.
- Кнопка **«Открыть в»** запускает выбранный клиент только при готовом сервере; если клиент не установлен, программа предлагает команду установки и ссылку на документацию.
- При попытке открыть недоступные Open WebUI / Agent Office появится объяснение и переход к управлению или документации, а не молчаливый запуск браузера.
- Добавлен тест регрессии для смены клиента без работающего сервера и оформления выделения.

Все предыдущие настройки, профили и результаты сохраняются при обновлении через `install.sh`.
