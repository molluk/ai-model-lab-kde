# AI Model Lab v2 — CachyOS / Fish / KDE

Локальное управление llama.cpp, Open WebUI, Agent Office и ComfyUI. Все команды выполняются локально, никаких установок из сети. Android-проекты и `~/.pi/agent/models.json` не редактируются. Только Python stdlib.

## Установка

Распакуй архив, открой терминал Fish в папке `AI-Model-Lab-v2` и выполни:

```fish
bash ./install.sh
~/.local/bin/ai-model-lab-v2 doctor
```

Ярлыки добавляются в меню приложений KDE, а если найдена существующая директория рабочего стола — и туда. Старые ярлыки и скрипты сохраняются.

## Как пользоваться

- Нажми **AI Lab — Менеджер моделей**, выбери модель по номеру.
- После загрузки откроется меню действий: WebUI, Agent Office, вместе, OpenCode, остановка текущей модели, остановка управляемых сервисов, статус, GPU, быстрый speed-test, журнал, выход с сохранением сервера в фоне.
- Прямые ярлыки моделей тоже открывают это меню.
- Сервер работает в отдельной сессии и останется жив после закрытия терминала.
- Все llama.cpp модели используют локальный порт `8080`, одновременно на нём может работать только один сервер. Порт занят — менеджер ничего не убивает автоматически.
- Open WebUI — `systemctl --user start open-webui.service`, порт `3000`.
- Agent Office — вызывает твой действующий `~/.local/bin/start-agent-office.sh`, пытается получить адрес из лога либо `AI_LAB_OFFICE_URL`.
- ComfyUI — по пункту меню, запускается с найденным `venv/bin/python` на порту `8188`, если нет другого процесса на порту.

## Команды (Fish и Bash)

```fish
~/.local/bin/ai-model-lab-v2 menu
~/.local/bin/ai-model-lab-v2 doctor
~/.local/bin/ai-model-lab-v2 status
~/.local/bin/ai-model-lab-v2 start blend-q4 --menu
~/.local/bin/ai-model-lab-v2 start coder-30b-ud --dry-run
~/.local/bin/ai-model-lab-v2 stop
~/.local/bin/ai-model-lab-v2 stop-all --ask
~/.local/bin/ai-model-lab-v2 stop-all --ask --include-legacy
~/.local/bin/ai-model-lab-v2 speed
~/.local/bin/ai-model-lab-v2 discover
```

Профили лежат в `~/.local/share/ai-model-lab-v2/models.json`. Конфиг не перезаписывается при повторной установке. Если определённая модель лежит в другом месте — исправь её `path`; для дополнительных моделей добавь профиль по образцу. Команда `discover` перечисляет все GGUF (исключая mmproj), но **не запускает неизвестные архитектуры автоматически**.

### Проверка совместимости

В случае ошибки флага llama.cpp используй `--dry-run` и `llama-server --help`, затем сравни с логом `~/.local/state/ai-model-lab-v2/logs/`. Профили 128K подтверждены прежними тестами для Blend Q4, Qwen3.8 Q4 и Qwen3-Coder Q4. Профили Q5 / Devstral 32K, UD 96K и VL 32K — стартовые предположения на базе прежних скриптов, они требуют фактического тестирования после миграции. Во всех профилях KV q8_0 размещается в RAM через `--no-kv-offload`.

Если Pi использует модель, значение `contextWindow` в `~/.pi/agent/models.json` должно соответствовать фактическому контексту сервера. Менеджер лишь предупреждает, **не правит Pi**.

### Speed-test

Лёгкий запрос к локальному `http://127.0.0.1:8080/v1/chat/completions` с сохранением входных/выходных токенов, общего времени, VRAM и таймингов, если сервер их возвращает. Указанная скорость `output tokens / wall time` **включает prefill** и не является decode-only tok/s. Результаты сохраняются в `~/.local/state/ai-model-lab-v2/benchmarks/`. Для официальных Android-бенчмарков продолжай использовать **ai-benchmark.py**.

### Безопасная остановка

`stop` завершает **только** сервер, запущенный этим менеджером, проверяя PID, начало процесса и исполняемый файл. `stop-all` дополнительно пытается остановить управляемый ComfyUI, Agent Office из твоего PID-файла и `open-webui.service`. **Чужие и старые процессы по умолчанию не убиваются**. Для старого llama-server есть отдельный пункт `L` (либо `--include-legacy`): показывает PID и командную строку, требует явного ввода `ОСТАНОВИТЬ СТАРЫЕ` и посылает SIGTERM только точному исполняемому файлу твоего llama.cpp от твоего UID. Это может прервать активный бенчмарк — используй осознанно. Если старый `start-qwen3-30b*.sh` уже запустил сервер на 8080, новая программа сообщит о конфликте. Закрой старый сервер вручную в исходном терминале. Никаких `pkill -f` или убийства всех OpenCode-процессов.

### Что НЕ удалять

- `pi` — менеджер Pi.
- `hf` и `tiny-agents` — pipx Hugging Face, требуются соответствующим командам.
- `open-webui` — uv entrypoint программы.
- `games` — независимый launcher игр.

После проверки всех новых ярлыков можно архивировать, а затем удалить старые `ai-menu.sh`, `ai-stop.sh`, `start-qwen3-30b*.sh`, `start-qwen3-vl-30b.sh` и их старые `.desktop`, **только если они нигде больше не вызываются**. Старые `start-agent-office.sh` и `start-comfyui.sh` пока оставить.

### Ограничения

- Профили оставлены в одном порту 8080; одновременная работа нескольких LLM-серверов на разных портах пока не реализована.
- «Остановить все» относится к известным управляемым сервисам, не убивает произвольные процессы с похожими именами.
- Внешний браузер и Open WebUI могут иметь собственные настройки безопасности и подключения.
- Временные измерения не заменяют полноценный `ai-benchmark.py`.
