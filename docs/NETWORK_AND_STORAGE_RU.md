# Сеть модели и очистка данных AI Model Lab

## Доступ к сети отдельно для каждой модели

На вкладке **Модели** справа, под выбором клиента Pi/OpenCode, находится
кнопка **«🌐 Клиент: интернет разрешён»**. Нажатие предлагает сохранить
**«🔒 Клиент: интернет выключен»** для выбранного профиля.

**Область действия:** только **новые** сеансы Pi/OpenCode, запускаемые
через кнопку «Открыть в» в AI Model Lab. Это **не** системный файрвол:
сам `llama-server`, WebUI, уже запущенные сеансы и программы, запущенные
в другом терминале, продолжают использовать обычные сетевые настройки.
Локальная модель сама по себе обычно не выполняет HTTP-запросы; сетевые
инструменты чаще находятся в OpenCode/Pi.

Офлайн-режим устроен как реальная Linux-изоляция TCP/IP:

1. На CachyOS должен быть установлен `bubblewrap` (`bwrap`).
2. Новый клиент запускается через `bwrap --unshare-net`. Его TCP/IP
   пространство не имеет доступа к внешней сети.
3. Внутри пространства создаётся локальный HTTP-прокси на
   `127.0.0.1:<порт модели>`. Он отправляет запросы через
   **Unix-domain socket** родительскому процессу, который пересылает
   их исключительно на локальный TCP-порт выбранного `llama-server`.
4. Если `bwrap` отсутствует, создание network namespace не разрешено
   ядром или старт sandbox завершается ошибкой, запуска клиента **не
   происходит**. Не предусмотрено автоматического fallback к запуску
   без ограничения сети.
5. Настройка сохраняется **для каждого профиля** в `models.json` под
   ключом `client_network: "online"/"offline"`, с резервной копией.
   По умолчанию старые профили сохраняют разрешённый режим.

Это ограничение обычных IP-соединений клиентского процесса, **не защита
от злонамеренной программы с доступом к пользовательской файловой системе,
Unix-сокетам, D-Bus и процессам хоста**. Bubblewrap сейчас изолирует сеть,
но оставляет доступ к пользовательским файлам для работы с проектами.
Не используйте этот режим как единственную защиту при запуске непроверенных
моделей, расширений или команд от агентов.

Существует отдельный способ проверить наличие компонента без изменений:

    command -v bwrap

На некоторых системах администратор запрещает пользовательские пространства
имён. Требуется реальная проверка на CachyOS; CI без bubblewrap проверяет
состав и безопасный отказ, а не абсолютную сетевую изоляцию.

## Очистка кэша, логов и резервных копий

Во вкладке **Настройки → Общие настройки** нажми
**«🧹 Кэш / логи / резервные копии»**.

Программа предварительно подсчитывает количество файлов и объём по трём
категориям, затем предлагает выбрать:

- **Кэш приложения** (отмечен по умолчанию): `__pycache__`,
  `tests/__pycache__`, `benchmarks/__pycache__`, `data/cache`,
  `data/tmp`.
- **Логи** (не отмечены по умолчанию): `data/logs`. Логи
  текущих активных процессов исключаются. Лучше выполнять чистку
  после остановки тестов и дополнительных сервисов.
- **Резервные копии** (не отмечены по умолчанию): `data/backups`.
  Удаляются старые копии кода и конфигурации, поэтому возможность
  отката из них теряется. Удаление требует отдельного подтверждения.

При выборе «Удалить выбранное» приложение повторно показывает количество
и объём; до подтверждения ничего не удаляется.

**Никогда не удаляются этой функцией:** действующие `models.json`,
`settings.json`, `services.json`, файлы GGUF/safetensors,
`data/reports` и `data/clients` (включая настройки Pi/OpenCode).
Удаление не выходит за пределы белого списка каталогов программы и
не следует по символическим ссылкам. Файлы, изменённые после
предпросмотра, пропускаются.

Никаких прав root, передачи данных в сеть или сторонних программ
для очистки не требуется.

## Таймер автоматической очистки кэша

**Настройки → Общие настройки программы**: включи
«Автоматически очищать кэш каждые», задай интервал **1–720 часов**
и нажми «💾 Сохранить настройки программы».

- Автоочистка **изначально выключена**. Она касается только кэша AI Model
  Lab: каталогов `__pycache__`, `data/cache`, `data/tmp` и прочих
  перечисленных в таблице выше. **Логи, бэкапы, отчёты, настройки,
  конфигурации Pi/OpenCode и GGUF не удаляются таймером.**
- Проверка расписания выполняется раз в минуту, только пока AI Model Lab
  открыт (включая свёрнутое в трей окно). Приложение **не устанавливает
  systemd-службу**, таймер Linux, cron или отдельный постоянно работающий
  процесс.
- Интервал и следующее время очистки **сохраняются**. Если дата наступила,
  пока приложение было закрыто, операция будет выполнена на следующем
  запуске, когда оно простаивает.
- Если запущен тест, выполняется операция или есть активные
  управляемые модельные процессы, очистка откладывается. Задержанная
  операция не копится в очередь: выполняется не более одной при
  наступившем интервале.
- При каждом новом интервале отсчёт начинается заново. Повторное
  сохранение **неизменённого** интервала не отодвигает следующее событие.
  Состояние сохраняется в `data/auto_cache_cleanup_state.json` и не
  удаляется ручной очисткой кэша.
- Файловая блокировка исключает одновременную автоочистку двумя
  экземплярами программы; механизм удаления повторно сверяет
  идентификаторы файлов. При ошибке повторная попытка откладывается
  на один час; в интерфейсе показывается причина последнего сбоя.
- Статус под настройкой показывает следующую очистку, последний запуск,
  количество удалённых файлов или последнюю ошибку.

**Важно:** автоматический запуск **не удаляет логи и резервные копии**.
Для них сохраняется ручное удаление с предпросмотром и подтверждением.

## Тесты

- `tests/test_offline_client.py`: безусловный отказ без bwrap,
  команда sandbox с `--unshare-net`, фиксированный loopback-сокет,
  два этапа проксирования, клиент не запускается напрямую.
- `tests/test_artifact_cleanup.py`: сохранность действующих
  настроек, GGUF, логов работающих моделей, игнорирование symlink,
  ограниченные каталоги и защита от изменения файлов после
  предпросмотра.
- `tests/test_gui_network_storage_qt.py`: настоящая Qt-функция
  переключения режима сети и диалог очистки без затрагивания
  профилей и отчётов.

Ветка `feature/per-model-offline-clients-storage-cleanup`; автоматическое
слияние с `dev` и `main` запрещено.
