# Windows 10/11 — план портирования (экспериментальная ветка)

**Статус:** подготовлена инфраструктура сборки и загрузки GUI, **не выпуск для пользователей**.

Существующее приложение написано на Qt6/PySide6, поэтому интерфейс можно
использовать на Windows без переписывания. Но API управления процессами
специфичны для Linux. На текущем этапе сборка `.exe` не означает, что
управление серверами, остановка и тестирование моделей работают на Windows.

## Схема Git

- `main` — проверенная стабильная Linux-версия;
- `dev` — интеграция проверенных доработок;
- `feature/windows-10-11-support` — Windows-порт, от `dev`.

## Отдельная Windows-сборка

На Windows 10/11 с установленным Python 3.11 x64 и Git:

```powershell
python -m pip install -r windows/requirements-build.txt
powershell -ExecutionPolicy Bypass -File windows/build.ps1 -SkipInstall
```

Сборка через PyInstaller создаёт `dist/AI-Model-Lab/AI-Model-Lab.exe`.
Формат `onedir` выбран для предсказуемой упаковки Qt-плагинов и ресурсов.
`install.sh` остаётся только для Linux, Windows использует отдельный PowerShell-файл.

Не копируй конфигурации `models.json`, `settings.json` и `services.json`
в публичный Git. На Windows пользовательские данные будут храниться
в `%LOCALAPPDATA%\AI-Model-Lab\`, а на Linux останутся в установленном каталоге.

## Этапы (текущий — первый)

1. [x] Отдельная Windows-сборка, `platform_paths`, stdlib-lock и Windows CI smoke.
2. [ ] Безопасные PID identity и остановка процессов на Windows без `/proc`, `os.killpg`.
3. [ ] Несколько `llama-server.exe` на разных GPU/портах, CUDA UUID и проверка владельца.
4. [ ] Windows-запуск Pi/OpenCode, WebUI, Agent Office, ComfyUI, бенчмарков.
5. [ ] RAM/CPU/GPU метрики, безопасное завершение, RU/EN локализация ошибок.
6. [ ] Реальные тесты на Windows 10 и Windows 11; подпись и установщик.

До выполнения второго этапа **не считать Windows-процессы управляемыми**:
Linux-код использует `/proc` и не обладает достаточной проверкой владельца
на Windows. После проверки на реальных ОС добавим выпуск и обновления.

## Защита данных и совместимость

Не объединять рабочие каталоги Windows и Linux автоматически. Существующие
Linux-конфигурации, модели и отчёты сохраняются без миграции.
Для Windows нужен собственный `llama-server.exe` с CUDA-сборкой и
совместимые версии Pi/OpenCode. GGUF-файлы можно использовать повторно.

Windows 10 находится вне обычного срока поддержки Microsoft с 14.10.2025.
Тестировать совместимость можно, но для защищённых рабочих станций
предпочтительнее Windows 11 либо поддерживаемый Windows 10 ESU.
