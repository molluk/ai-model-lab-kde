# AI Model Lab KDE

**Русский** | [Все документы](INDEX.md) | [English](../README.md) | [Установка](INSTALL_RU.md) | [История версий](CHANGELOG.md) | [Участие в разработке](CONTRIBUTING.md)

**AI Model Lab** — экспериментальное графическое приложение на Python/Qt6 для запуска, мониторинга и тестирования локальных ИИ-моделей в Linux. Управляет независимыми серверами `llama.cpp`, подключает к выбранной модели ИИ-агентов и хранит результаты тестов.

> **Статус: экспериментальная версия (Alpha).** Основная целевая система — CachyOS / Arch Linux с KDE Plasma. Другие дистрибутивы, видеокарты и клиенты требуют отдельной проверки. Веса моделей приложение не скачивает.

## Возможности

- **Профили моделей:** добавление, редактирование, клонирование и удаление профилей GGUF; контекст, sampling, GPU/CPU layers, KV-кэш и мультимодальные параметры.
- **Несколько серверов одновременно:** отдельный процесс и локальный порт каждой модели, назначение NVIDIA GPU по индексу или UUID. Две модели могут использовать один GPU, если хватает ресурсов; VRAM видеокарт автоматически не объединяется.
- **Мониторинг:** загрузка GPU, VRAM, RAM, состояния процессов, живые журналы и история производительности.
- **Управление сервисами:** отдельные операции с `llama-server`, Open WebUI, Agent Office и ComfyUI — при наличии соответствующих установок. Веб-интерфейсы открываются во вкладке, в обычном окне браузера либо в отдельном окне без браузерных панелей (Chromium-совместимые браузеры).
- **ИИ-клиенты:** выбор Pi или OpenCode для каждой модели; запуск выбранного клиента на API *работающего* сервера без изменения глобальных настроек клиента.
- **Встроенные тесты:** скорость, числовые QA-задачи, синтетический контекст и примеры анализа Android-исходников; результаты остаются внутри приложения.
- **Системный трей KDE:** скрытие окна без остановки запущенных моделей. Профили и настройки сохраняются между запусками GUI.
- **Идентификация сборки:** внизу справа отображаются версия приложения и короткий SHA коммита; полный SHA — во всплывающей подсказке. При установке из каталога Git метаданные записываются вместе с установленным кодом.

## Требования

- Linux, Python 3.11+, Python-библиотека Qt6 (`pyside6` для CachyOS / Arch Linux).
- Собранный [llama.cpp](https://github.com/ggml-org/llama.cpp) с `llama-server` и хотя бы один совместимый GGUF-файл.
- Для NVIDIA-мониторинга и привязки GPU: рабочие драйверы/CUDA и `nvidia-smi`.
- Необязательные внешние инструменты: [Pi](https://github.com/badlogic/pi-mono), [OpenCode](https://opencode.ai/), [Open WebUI](https://github.com/open-webui/open-webui), Agent Office и ComfyUI. Устанавливаются отдельно.

## Быстрая установка (CachyOS / Arch)

```bash
sudo pacman -Syu pyside6
python3 release_preflight.py
bash ./install.sh
~/.local/bin/ai-model-lab
```

Установщик по умолчанию копирует приложение в `~/AI/AI-Model-Lab` (можно изменить через `AI_MODEL_LAB_HOME`) и создаёт ярлык KDE. GGUF-файлы не копируются. После установки укажи реальные пути в профилях моделей.

Полная инструкция: **[INSTALL_RU.md](INSTALL_RU.md)**. Английская версия: **[INSTALL.md](INSTALL.md)**.

## Первый запуск

1. На вкладке **«Модели»** выбери профиль → **«Изменить»**. Укажи путь к GGUF, `llama-server`, контекст, GPU и уникальный API-порт. Сохрани профиль.
2. Нажми **«Запустить модель»** и дождись состояния готовности. Попытка открыть Pi/OpenCode до загрузки модели намеренно блокируется.
3. Рядом с кнопкой **«Открыть в»** выбери Pi либо OpenCode. Само изменение списка только сохраняет предпочтение и **не запускает** сервер.
4. Используй вкладку **«Тесты»**, отчёты смотри на вкладке **«Отчёты»**.
5. Останавливай нужный экземпляр на вкладке **«Управление»** либо закрывай только GUI, оставляя модели в фоне.

## Где хранятся данные

| Данные | Расположение |
|---|---|
| Профили моделей | `models.json` в установленной папке |
| Настройки приложения | `settings.json` |
| Метаданные процессов | `data/instances/` |
| Логи | `data/logs/` |
| Отчёты | `data/reports/` |
| Отдельные конфигурации агентов | `data/clients/` |

В публичном репозитории находятся только образцы `models.example.json` и `settings.example.json`. Реальные конфигурации, ключи, логи, чаты и GGUF **нельзя** коммитить. Примерные профили нужно настроить перед использованием.

## Проверка разработчика

```bash
python3 release_preflight.py
python3 -m unittest discover -s tests -v
```

Автоматические тесты не подтверждают работу GUI на каждом окружении KDE и фактическую загрузку всех CUDA-моделей.

## Безопасность

- Pi/OpenCode могут получать права на чтение или изменение файлов по своим настройкам. Перед работой с закрытыми проектами настрой ограничения. Наличие только инструментов чтения в промпте **не означает** изоляцию на уровне ОС.
- Не публикуй `models.json`, `settings.json`, `data/`, токены, историю чатов, приватные Android-проекты и веса моделей.
- По умолчанию локальные API привязаны к `127.0.0.1`. Не открывай порт наружу без отдельной настройки безопасности.

Подробнее: [SECURITY.md](SECURITY.md) и [HISTORY_PROVENANCE.md](HISTORY_PROVENANCE.md).

## Пользовательские AI-сервисы
Вкладка **Управление** позволяет добавлять собственные локальные сервисы.
Укажи ID, название, команду запуска, рабочую папку и (по желанию) адрес
локальной проверки готовности и URL интерфейса. Команда запускается напрямую,
без shell, с правами твоего пользователя. У каждого сервиса — единая кнопка
«Запустить/Остановить»; чужие PID и процессы приложение не завершает.
Конфигурация сервисов сохраняется в локальном `services.json`, исключённом
из Git; примеры — в `services.example.json`.

### Полный выход

При закрытии окна доступны **Свернуть в трей**, **Закрыть без остановки**, **Закрыть и остановить все управляемые AI-сервисы** и **Отмена**. Полный выход отправляет SIGTERM только процессам с подтверждённой принадлежностью AI Model Lab, останавливает настроенную службу WebUI через `systemctl --user` и проверяет результат. Чужие серверы и отдельно запущенные Pi/OpenCode не завершает. При ошибке остановки оставляет окно открытым для диагностики. Во время теста сначала нужно завершить тест.
